# 面试要点（AI 工具箱）

> 用法：先自己口头回答，再看参考答案。目标是掌握论证结构，用自己的话复述，而不是背诵。

## 1. 一分钟项目介绍

「我做过一个部署上线的个人 AI 工具箱，地址是 horseforever.cn，代码在 GitHub 上。它有四个模块：首页每天展示诗词、英文句子和名画并配 AI 赏析；日报推送每天早晨九点把科技和时政新闻的 AI 摘要发到我邮箱；页面总结能把任意文章链接转成结构化摘要；命理小站输入生日，后端用确定性算法算出八字命盘，再用 RAG 检索我自建的命理知识库，让大模型生成解读。技术上前后端分离——Next.js 静态站加 FastAPI 后端，Nginx 部署，SQLite 存储，systemd 管理服务。最大的亮点是一层模型路由：简单任务走本地 Ollama 的 7B 模型，复杂任务走云端 DeepSeek，每一层都有降级兜底。项目从课程 demo 两次重构而来，提交历史完整。」

讲完停住，「模型路由」是留给面试官追问的钩子。

## 2. 架构与工程化

**Q：为什么前端静态导出，不上 SSR？**
内容以天为单位更新、无个性化首屏，SSR 收益为零；静态文件 Nginx 直接命中、无 Node 常驻进程、故障面最小。

**Q：为什么前后端分离，不用 Next API Routes？**
后端是项目主体（模型调用、定时任务、数据管道），FastAPI 校验与生态更合适；后端可被任意前端复用；静态导出模式下 API Routes 本来就不可用。

**Q：为什么 SQLite 不上 MySQL？**
单机低频场景，SQLite 零运维；访问全部收口在 db.py 一层，换 MySQL 只改这一层。选型看访问模式，不追名词。

**Q：为什么定时任务用 systemd timer，不用 APScheduler？**
定时任务与 Web 服务解耦：Web 崩溃不影响早报；多 worker 不会重复触发；独立日志与启停。应用内调度器在单机还行，多进程就出问题。

**Q：为什么 uvicorn 单 worker？**
SQLite 单文件写库，多 worker 引入锁竞争；手动早报的内存状态是单进程的；个人站点并发下单 worker 够用。将来扩容先拆状态与存储（见 README 路线图）。

**Q：服务挂了怎么办？**
systemd Restart=always 自动拉起；日志双通道（journald + 滚动文件）；全局异常兜底返回统一 JSON 错误，不泄露堆栈。

## 3. 模型路由

**Q：讲讲模型路由层。**
任务按输出长度、质量要求、时延容忍度分两档：fast（新闻分类、短赏析）优先本地 qwen2.5:7b——零 API 成本、数据不出服务器；quality（长文摘要、命理解读）优先 DeepSeek——质量必须保。每档首选失败自动切备选，全挂才抛业务错误；每次调用记录实际 provider。

**Q：为什么不上 70B/100G 本地模型？**
硬件账：8G 内存装不下（需 64G+）、60G 盘放不下、4 核 CPU 跑 70B 不到 1 token/s。7-8B 量化是这台机器的天花板。架构已留升级路径：换 GPU 服务器后只改 .env 配置。

**Q：模型输出格式不可靠怎么办？**
structured.py 统一处理：json_mode + Pydantic schema 校验，坏 JSON 自动追加提醒重试一次，再失败业务层降级（解读失败仍返回命盘、摘要失败给中文错误）。

## 4. 科技早报

**Q：新闻从哪来？怎么选源的？**
7 个源全部实测过连通性：科技（少数派/爱范儿/IT之家 RSS + Hacker News 官方 API）、国内时政（新华网时政）、国际类（新华网国际 + 中新网国际，国内站无网络风险）。被淘汰的（36氪反爬、虎嗅无 RSS）实测记录在案。源列表是插件式配置。

**Q：50/15/20/15 配比怎么实现？**
每个源打类别标签；国际类由 fast 档模型按标题摘要二分类（时政/生活），模型挂时降级关键词规则；取数用最大余数法按配额切名额；某类源全挂配额自动让渡——早报可少一类，但不断更。

**Q：怎么去重？重复跑会重复发吗？**
url_hash 数据库唯一约束（INSERT OR IGNORE），重跑幂等；digests 表按日期覆盖写，同天重复触发只更新不重发。

**Q：邮件失败怎么办？**
sent_at 为 NULL 的下轮自动补发；SMTP 未配置走模拟模式（HTML 写本地文件）；邮件只是末端通知，网页版早报永远可查。

## 5. 命理小站与 RAG

**Q：八字怎么算的？为什么不用大模型？**
lunar-python 确定性计算（四柱/五行/十神/纳音/大运起运/黄历宜忌），与万年历人工核对过、有单元测试。LLM 算干支必错（幻觉重灾区）且不可测试。原则：可计算的交给代码，需要语言组织的才交给模型。

**Q：讲讲 RAG 链路。**
自建知识库 7 个 Markdown（公开资料概念 + 原创撰写）→ 按二级标题切 33 块 → 向量化入库 → 按命盘特征构造检索词（日主/某五行旺/缺某行）→ 余弦 top-k → 拼进提示词 → DeepSeek 生成结构化解读。

**Q：为什么不上向量数据库？**
知识库几十块，暴力余弦毫秒级；向量数据库要常驻进程、多故障点，对这个规模是过度设计。检索层接口化，规模上来再换。

**Q：向量化挂了怎么办？**
降级链：bge-m3（本地）→ 字符 bigram 稀疏向量精确匹配（零依赖、零碰撞）；查询时 bge-m3 不可用自动重建 ngram 索引。检索永远可用。

**Q：怎么控制 LLM 胡说八道？**
三层：命盘数据代码算的、模型改不了；提示词限定只依据检索内容、知识库没有的不许编；结构化输出 Pydantic 校验 + 重试 + 最终降级（只返回命盘）。页面有「仅供传统文化参考」免责声明。

**Q：为什么解读要缓存？**
同生日+时辰+性别只生成一次，重复查询秒回、零 token 成本。缓存是成本控制，也是响应速度优化。

## 6. 页面总结与首页

**Q：正文提取怎么做？**
trafilatura 可读性库（内置大量站点模板与降级策略），比手写正则可靠；超长正文截断到 5000 字符防 token 爆炸；提取过短判定为登录页/图片页给中文错误。

**Q：首页三区怎么保证可用？**
三个免费 API（今日诗词 / quotable / 大都会博物馆）+ 内置兜底数据集（按日期哈希轮换）+ 按日期缓存（一天只调一次第三方和模型）。第三方全挂首页也永远有内容——这条在开发期被真实演练过。

## 7. 整体问题

**Q：项目和你课程 demo 什么关系？**
两次重构都在 git 历史里：纯前端 → FastAPI + SQLite → 这次加工程化地基（配置/日志/错误/测试）和四个 AI 模块，部署资产入库。提交记录就是项目生长史。

**Q：最大难点？**
① 模型路由的降级链——把每个 provider 可能的超时/报错/坏格式收敛成业务层无感的可靠调用；② 命理模块的边界划分——想清楚什么用代码算什么用模型，比写代码难；③ 新闻源选型——把「网络不可达」从运行时风险变成选型时已排除的风险。

**Q：日活 10 万怎么扩？**
静态资源上 CDN；API 无状态直接多开 worker + Nginx 负载均衡；热点接口（/api/daily）加缓存层；SQLite 换 MySQL（存储层已抽象）；早报独立脚本本来就不占 Web 资源。

**Q：安全做了什么？**
密钥走 env 不入库；SQL 全参数化；CORS 白名单精确到域名；无用户体系无账号攻击面；错误响应不泄露堆栈；服务用专用系统用户运行（不用 root）。

**Q：成本？**
固定成本服务器月费；变动成本 DeepSeek 按量计费——分类/短赏析走本地模型免费，quality 任务有缓存控制调用量。

**Q：这个项目要多少服务器资源？4 核 8G 是过剩吗？**
资源大头是本地模型：qwen2.5:7b 加载约需 5G 内存 + bge-m3 约 1.2G，加上系统与 Web 服务，8G 内存是「刚好」而非过剩；2G 内存装不下 7B 模型（连加载都做不到）。如果砍掉本地模型层全走云端，2C2G 就能跑——但那等于砍掉「模型路由」这个核心亮点，省的钱远不值失去的架构叙事。降级底线是 2C4G + 换 3B 模型。4 核的意义在本地推理速度（CPU 推理吃核数）。结论：当前配置与架构是匹配的，不是浪费。

**Q：AI 帮你写了多少？（必答题）**
「架构设计、技术选型、每个模块的取舍是我主导的，AI 编程助手帮我实现和检查细节。我对每一处设计都能解释为什么这么做——你可以随便挑一个模块问。」然后靠上面的储备证明。2026 年语境下「会用 AI 协作」是加分项，「只有 AI 会」才是减分项。

**Q：后续规划？**
README 路线图：博客文章系统、用户订阅体系、RSSHub 扩源、GPU 升级后切换更多本地任务。说一两个即可。

**Q：命理功能会被质疑不科学吗？**
定位：传统文化解读工具 + RAG 工程实践载体。讲技术（确定性计算、知识检索、结构化生成、容错），不宣传任何预测效力，页面有免责声明。

**Q：git推送问题**
浏览器读系统代理设置所以能翻墙；git 是命令行工具，从来不读系统代理，必须给它单独配置——这是「系统代理 vs 程序自觉」的区别在 git 上的具体体现。
